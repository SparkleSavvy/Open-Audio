Admin CLI reference

The entire management surface behind one entry point: npm run admin.

All commands share one shape: npm run admin <entity> [id] <action>. Every invocation is recorded in the admin_log audit table. Older spellings such as npm run admin owner still work as aliases.

Accounts

account owner [username]Create or reset the owner account
account admin [username]Create or reset a moderator account
secretRotate JWT_SECRET in .env (invalidates all sessions)
removal-keyGenerate / rotate REMOVAL_KEY

Users

usersList users
user <id|username>Show a user
user <id> ban|unbanBan / unban
user <id> promote|demoteChange role (the owner cannot be changed here)
user <id> supporter [on|off]Grant / revoke the Supporter badge
user <id> password [pw]Reset a password (prompts if omitted)

Tracks

tracks [status]List by status: pending, verified, suspended, rejected, all
track <id>Show a track with quality and category
track <id> verifyPublish
track <id> suspend|unsuspendEnable / disable playback
track <id> reject <reason>Reject with a reason
track <id> resubmitSend a rejected track back to the queue
track <id> deletePermanently delete

Maintenance

scan [--all]Backfill track metadata from files
backup [dir]Snapshot DB (VACUUM INTO) + copy uploads
restore <dir> --forceRestore from a snapshot folder
vacuumintegrity_check + VACUUM
prune [--delete]Report (or remove) orphaned files
purge-inactive [months]List accounts inactive for months (default 19)
purge-inactive <m> --deleteDelete them (owner/admins/supporters protected)
notify <id|username> <msg>Send a manual notification

purge-inactive --delete removes likes, comments, reposts, follows and notifications of removed accounts, while their tracks remain (ownerless). Add --include-admins / --include-supporters to lift the default protections.

Server

statusServer state, owner/moderation info, statistics
removal-keyRotate REMOVAL_KEY
remove-server [reason]Request full server removal (confirmed in UI by owner)
