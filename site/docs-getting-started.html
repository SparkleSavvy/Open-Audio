Install & first launch

From git clone to a verified track in about two minutes. No external database, no native modules.

Open Audio needs exactly one runtime dependency: Node.js itself. Everything else — database, web server, file storage — is built in.

Requirements

  • Node.js 22.5+ — Node 24+ recommended for stable node:sqlite.
  • Windows, macOS or Linux — there are no native modules to compile.
  • About 40 MB of disk plus room for your library.

Quick start

quick start 
$ npm run setup              # deps + .env + SQLite + owner account
$ npm run dev                # API :4000 · web :3000

# production
$ npm run build && npm start # SPA + API + files on :4000

npm run setup installs dependencies, writes .env from .env.example, creates the SQLite schema, and provisions the owner account. The generated owner password and the removal key are printed once in the console.

Re-running setup is safe — it never resets the owner password unless you provide a new one via OWNER_PASSWORD.

Default environment

.env 
PORT=4000
DATABASE_PATH=./data/open-audio.db
UPLOAD_DIR=./uploads
JWT_SECRET=<generated automatically>
REMOVAL_KEY=<generated automatically>
OWNER_USERNAME=owner
OWNER_EMAIL=owner@example.com
# OWNER_PASSWORD=TestPass123  (printed by setup)

The full list of environment variables — including Docker/Kubernetes overrides like COOKIE_SECURE and TRUST_PROXY — lives in the deployment guide.

Your first track

  1. Open http://localhost:3000 (dev) or :4000 (prod) and register an account.
  2. Go to Upload, pick an Opus or lossless file — title, artist, duration and cover fill themselves from tags.
  3. The track enters the pending queue, visible under My uploads (/me).
  4. Sign in as the owner, open /admin → Moderation, preview the track and hit Verify.
  5. The track is now public in feed and search, downloadable, and its author got a notification.

Production on a Linux server

The bundled open-audio bash utility manages the whole machine-level lifecycle, including a systemd service:

server install 
chmod +x open-audio
sudo ./open-audio self-install             # -> /usr/local/bin/open-audio
sudo open-audio install --service          # deps + owner + systemd unit
sudo open-audio config set JWT_SECRET "$(openssl rand -hex 32)"
sudo open-audio config set REMOVAL_KEY "$(openssl rand -base64 24)"
sudo open-audio config set OWNER_PASSWORD "change-me"
sudo open-audio start
sudo open-audio status                     # mode, port, health

Behind nginx or Caddy, enable HTTPS and set COOKIE_SECURE=1 / TRUST_PROXY=1. Container-based paths are described in Deployment.
