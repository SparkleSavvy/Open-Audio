Deployment guide

One process, two volumes. Everything you need to run Open Audio outside your laptop.

Topology

A single Node process serves the built SPA, the REST API and uploaded files from port :4000. State lives in exactly two places, both of which belong on a persistent volume:

  • SQLite database (DATABASE_PATH, WAL mode) — one writer only.
  • Uploaded media (UPLOAD_DIR).

GET /api/health is provided for container probes.

Environment

VariableNotes
NODE_ENVset to production (refuses weak JWT_SECRET otherwise)
JWT_SECRET≥16 chars; shared by all replicas; rotates sessions
REMOVAL_KEYrequired for the removal flow; openssl rand
DATABASE_PATHinside the persistent volume
UPLOAD_DIRinside the persistent volume
COOKIE_SECURE1 behind HTTPS
TRUST_PROXY1 behind a load balancer / Ingress
HELMET_CSP1 enables strict CSP + HSTS
OWNER_*owner account provisioned idempotently on boot

In containers these values win over any persisted .env, so every replica sees the same secrets.

Docker (single host)

docker compose 
$ cp .env.example .env    # set JWT_SECRET, REMOVAL_KEY, OWNER_PASSWORD
$ docker compose up -d --build
# -> http://localhost:4000

The sparkle-data volume holds the database and uploads; the image builds on node:24.

Kubernetes

Manifests live in k8s/: namespace, configmap, secret, PVC, deployment, service, ingress. Secrets are not committed — create the Secret first:

kubectl 
kubectl apply -f k8s/namespace.yaml

kubectl -n sparkle-audio create secret generic sparkle-audio \
  --from-literal=JWT_SECRET=$(openssl rand -hex 32) \
  --from-literal=REMOVAL_KEY=$(openssl rand -base64 24) \
  --from-literal=OWNER_PASSWORD=$(openssl rand -base64 18) \
  --from-literal=OWNER_EMAIL=owner@example.com

kubectl apply -f k8s/ -n sparkle-audio

The Deployment runs one replica with a ReadWriteOnce PVC, probes on /api/health, and an nginx Ingress raised to a 64 MB body limit (tracks reach 60 MB). The container entrypoint runs non-interactive setup from env, then starts the server.

Scaling limits

  • Database — SQLite allows a single writer; horizontal scale means moving to Postgres.
  • Uploads — local disk; shared volumes need sticky sessions.
  • Rate limiting — the limiter and brute-force maps are in-process; behind N pods limits are per-pod, not global (swap in Redis).
Run replicas: 1 and scale the node vertically until one of the above is replaced.

The open-audio utility

The system-level companion script handles service, volumes and env for native or Docker modes:

install [--service]deps + owner (native) or build+run (docker); systemd unit with --service
start / stop / restartcontrol the instance
status / health / logs [-f]state, probe, journalctl/docker/file logs
config list|get|set|edit|secretmanage .env (masked; restarts on change)
updatepull + reinstall/rebuild + restart
backup [dir] / restore <dir>snapshot via the admin CLI
mode native|dockerswitch deployment mode (persisted)
uninstall [--purge]stop + remove; --purge wipes data
remove [--yes] [reason]app-level removal flow (confirmed in UI)
